Universal SSO launcher system

Functional description of scripts/run-example.sh, scripts/provider-check.sh and scripts/sso-common.sh, and how they fit the gateway lifecycle scripts, the Makefile and the test suites. Module github.com/universal-sso/universal-sso. Source of truth: the scripts themselves.

1. Executive summary

The launcher gives the five example clients (Rust, Go, Python, Java, C#) and the three OIDC vendor adapters (Okta, Auth0, Microsoft Entra ID) the same guided start that make google-check and make google-url give Google. Before this work, nothing built a client, started a gateway and confirmed that a provider was registered. The user had to do those steps by hand.

Scope of verification. The Okta, Auth0 and Entra adapters were exercised only against the in-process fake identity provider (pkg/sso/oidc/oidctest), never against a live tenant. real mode validates your configuration and prints the sign-in URL. It does not complete the sign-in for you, and it has not been run against a real Okta, Auth0 or Entra tenant. provider-check.sh checks configuration only.

2.2 Data flow

  1. The launcher resolves example, mode and provider, then checks the toolchain.
  2. It builds ssod (with -tags e2e in e2e mode) and starts a gateway, or reuses the project gateway in real mode.
  3. It reads GET /providers and stops with a message if the chosen provider is missing.
  4. It builds the client and runs it with SSO_GATEWAY_URL, SSO_PROVIDER and SSO_EXPECTED_IDP_HOST set.
  5. The client asks the gateway for /auth/{provider}/login and gets a redirect carrying state and a PKCE S256 challenge.
  6. In mock and e2e, the client follows the redirects on the gateway host and the callback returns the profile. In real mode the client prints the URL and the browser completes the flow.

Tokens stay in the gateway. The callback returns only the user profile as JSON.

3.4 Settings checker: provider-check.sh

provider-check.sh <okta|auth0|azure> [--env FILE] [--online] is the vendor counterpart of make google-check. It is read-only and prints one [OK], [WARN] or [FAIL] line per rule, each failure with a fix.

RuleApplies toResult when broken
SSO_STATE_SECRET set, not starting with change-this, at least 32 bytesallFAIL
SSO_SERVER_PORT is not 5000 on macOSallFAIL
Client id and client secret are not empty or samplesallFAIL, with the note that the provider stays off
Issuer URL set, not the sample host, https (http only for loopback)okta, auth0FAIL
Tenant is a GUID, a domain, or common, organizations, consumersazureFAIL
Multi-tenant endpoint without ALLOWED_TENANTSazureWARN: any tenant the endpoint admits can sign in
ALLOWED_TENANTS entries are GUIDsazureFAIL
Redirect URI ends in /auth/<id>/callback and host matches SSO_SERVER_BASE_URLallWARN
Discovery document reachable (--online)allFAIL

On success it prints the exact redirect URI to register in the vendor console. Exit codes: 0 ready, 1 at least one FAIL, 2 bad usage.

3.6 Execution flow and error handling

The launcher validates early and fails with one clear sentence. Nothing is built before the cheap checks pass.

StageFailureMessage and exit
Argumentsunknown example, mode or option, missing valueERROR: ... plus a pointer to --help, exit 2
Portnot 1024 to 65535, or 5000exit 2. Port 5000 is reserved for AirDrop on macOS
Providersaml or oauth2exit 2: no adapter yet, with the list of providers that work
Providervendor provider in mock mode, google in e2eexit 2, with the mode that does support it
Preflightmissing curl, Go or client toolchain, old Python or JDKexit 1, names the tool and how to get it
Real configno .env, or settings fail the checkexit 2 or 1, with the fix lines. Nothing is started
Port in useanother program holds the portexit 1, suggests --port N
Gateway startexits early or never answers /healthzexit 1, prints the last five log lines
Registrationprovider missing from /providersexit 1, shows the registered list and, in real mode, reminds you to make restart after editing .env
Clientbuild, check or login failsexit 1 with the client's own message
Sign-in (mock, e2e)no signed in via <provider> lineexit 1, points to the gateway log

A trap on EXIT stops the throw-away gateway even when a later step fails. A previous throw-away gateway on the same port is replaced, which makes a repeat run safe.
